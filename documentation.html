Master DND

Complete Architecture, Tech Stack, Workflow & API System Documentation

Executive Abstract

Master DND provides a unified mobile and cloud-synchronized control center that automates, profiles, and orchestrates how smartphones maintain silence. The system integrates Flutter client-side state management using BLoC pattern with a resilient Node.js, Express, and MongoDB Atlas cloud backend.

2. System Workflows & User Lifecycle

The Master DND application follows a deterministic state machine orchestrated through AuthBloc and DndBloc.

Authentication & Onboarding Workflow

1

Session Validation (AuthGate / Splash)

The application loads and dispatches AuthCheckRequested. AuthBloc checks local storage for a cached JWT token. If present, it calls GET /api/user/profile. If valid and isProfileComplete == true, it immediately mounts the Dashboard. If no token, it routes to PhoneLoginScreen.

2

Phone Submission & OTP Generation

User inputs their phone number with international country code. The client dispatches AuthSendOtpRequested(phone). The backend validates format (E.164), generates a cryptographically secure 6-digit code, stores it in MongoDB with 5-minute TTL, logs it, and emits AuthOtpSentState.

3

Verification & Account Creation

User enters the 6-digit code. The client dispatches AuthVerifyOtpRequested(phone, otp). The server checks attempts (≤ 5), matches the code, and creates a new User record in MongoDB Atlas if first-time, seeding default DND profiles (Sleep, Work, Meeting, Driving, Study). A 30-day JWT token is issued.

4

Profile Setup (Step 2 Onboarding)

If user.isProfileComplete == false, the client navigates to ProfileFormScreen. The user inputs their Name, Avatar, and Email. The client dispatches AuthCompleteProfileRequested which calls PUT /api/user/profile, sets isProfileComplete: true, and transitions to AuthenticatedState.

5

Dashboard Operations & Edit Profile

The user lands on the Dashboard (AppShell). The header greets the user by name with a time-of-day greeting (morning/afternoon/evening) and displays their avatar. Tapping the avatar opens EditProfileScreen with verified phone badge, profile editing, and logout.

DND Power Arming & State Synchronization

[User Taps Power Button]

3. Database Models & Schema Design

MongoDB Atlas stores all application state across four core Mongoose collections.

1. User Collection (users)

Represents the primary user profile and system settings.

{
  "_id": ObjectId,
  "phone": "+19876543210", // indexed, unique
  "name": "Atulya Agrawal",
  "email": "atulya@example.com",
  "avatar": "A",
  "bio": "Mobile Engineer",
  "isProfileComplete": true,
  "dndEnabled": false,
  "emergencyContacts": [ ... ],
  "notificationPreferences": {
    "allowDndAccess": true,
    "allowContacts": true,
    "allowNotifications": true
  },
  "createdAt": ISODate,
  "updatedAt": ISODate
}

2. OTP Collection (otps)

Temporary verification tokens with automated TTL purging.

{
  "_id": ObjectId,
  "phone": "+19876543210", // indexed
  "otp": "123456",
  "expiresAt": ISODate,   // TTL index (5 mins)
  "verified": false,
  "attempts": 0,          // Max 5 attempts
  "createdAt": ISODate
}

3. DND Profile (dndprofiles)

Pre-configured & custom silent mode profiles.

{
  "_id": ObjectId,
  "userId": ObjectId,    // ref: User
  "name": "Sleep",
  "icon": "moon",
  "meta": "Priority only, 10 PM - 6:30 AM",
  "active": true,
  "mode": "priorityOnly",
  "autoReply": true,
  "hideNotifications": false,
  "callWhitelist": "Starred",
  "messageWhitelist": "VIP only"
}

4. DND Rule (dndrules)

Automated trigger conditions for profiles.

{
  "_id": ObjectId,
  "userId": ObjectId,    // ref: User
  "title": "Sleep schedule",
  "subtitle": "Starts 10:00 PM, every night",
  "triggerType": "schedule", // calendar, driving
  "active": true
}

4. REST API Specification

Method Endpoint Auth Required Description & Payload
POST /api/auth/send-otp No Request 6-digit OTP code. Body: { "phone": "+19876543210" }
POST /api/auth/verify-otp No Validates OTP, creates account, returns 30-day JWT Bearer token
GET /api/user/profile Bearer Token Returns authenticated user profile, phone, avatar, and DND status
PUT /api/user/profile Bearer Token Updates name, email, avatar, bio; sets isProfileComplete: true
GET /api/dnd/profiles Bearer Token Fetches list of all DND profiles belonging to the authenticated user
PUT /api/dnd/profiles/:id Bearer Token Updates profile configuration or switches active status
POST /api/dnd/toggle Bearer Token Toggles the master DND power state (armed vs disarmed)
GET /api/dnd/insights Bearer Token Returns silenced count, let through count, and weekly metrics

7. Security & Best Practices

  • E.164 Phone Formatting: Numbers are sanitized and validated to avoid duplicates across country formats.
  • Lockout Protection: OTP verification is locked after 5 failed attempts per window to prevent brute-forcing.
  • Atomic Token Refresh: Session tokens carry 30-day expirations and are invalidated immediately upon logout.
  • Platform Isolation: Package namespace is standardized to com.agree.masterdnd across Android Gradle, Kotlin manifests, iOS PBX projects, and macOS AppInfo bundles.
